# Trader presets vs investor vs hybrid (#3038)

**Question.** What does each *trader* dial contribute, measured as a coherent preset rather than
a one-knob graft onto the investor base? And how do the trader, hybrid and investor presets rank
over several horizons?

**Book basis.** See `docs/design/weinstein-book-reference.md` §4.6, resolved question 2026-09-29.
- The trader's buy is defined against the **30-week** MA, and the ideal trader entry is the
  continuation buy.
- The book calls the 10-week MA "best for traders to use" but never says what it is applied to.
- The 4–6 % automatic initial stop is the trader's fallback (§5.3).
- Traders exit as the Stage-3 top forms, and buy full size on the breakout.

## Reading rule (pre-registered 2026-09-29, before any cell runs)

1. **Gate.** Every paired read passes `validator_diff -check V6` at the same salt. A failing salt
   is reported and left out of that pair's reading. The thresholds below scale with the number of
   **valid** salts *n* for that pair:
   - **n = 3:** a verdict needs 2 of 3.
   - **n = 2:** a verdict needs 2 of 2; a 1–1 split reads "no reading".
   - **n ≤ 1:** "no reading" for that pair and window. The numbers are reported as descriptive only.
2. **Metrics per salt.** Calmar (primary), max DD, total return, trades. Also the paired per-salt
   differences, arm − H and arm − I, plus T2 − T1.
3. **Per-dial reading, within a window.**
   - **Continuation buys (T1 vs H).** Exactly one of four outcomes, using the valid-salt
     threshold from rule 1:
     - **"Adds":** T1's Calmar ≥ H's in the required number of valid salts, **and** T1's max DD
       is never > 5 pp worse at any valid salt.
     - **"Mixed — Calmar up, drawdown worse":** Calmar passes the threshold but max DD is > 5 pp
       worse at ≥ 1 valid salt. Reported as a trade-off, not as "adds".
     - **"Dilutes":** T1's Calmar is lower in the required number of valid salts.
     - **"No reading":** neither threshold is met (e.g. a 1–1 split at n = 2), or n ≤ 1.
     - Always report the per-entry-type split: continuation vs base-breakout trades, with count,
       realized P&L, win rate and median `pnl_percent`.
   - **10wk stage (T0 vs H).** Same four outcomes. The book prior says T0 should not beat H, so a
     T0 "adds" is flagged for investigation, not adopted.
   - **10wk trailing stop (T2 vs T1).** Same four outcomes, with T2 in T1's place and T1 as the base; the pair differs only in
     `trailing_stop_ma_period` (10 vs unset). Added 2026-09-30, before any cell ran. Also report
     the median holding period and the stop-exit share for both arms, since a shorter trailing
     MA is expected to exit earlier (`project_edge_is_the_fat_tail`: watch the winners' tail).
   - **The 26y window runs s0 only** until s1/s2 are added, so per-dial reads there are
     **descriptive only** (n = 1 → "no reading" under rule 1). The per-dial verdicts come from
     `5r` and `5d`.
4. **Preset ranking, per window.** Rank I / H / T1 (/ T2) by median Calmar across valid salts, and
   report max DD alongside.
   - A ranking that flips between `5r` and `5d` is reported as regime-dependent, not resolved.
   - `26` s0 is one salt: descriptive only unless s1/s2 run.
5. **Per-trade check for any arm that "wins".** Join the arm to its base (H; T1 for T2) on
   (entry date, symbol) and report. The key is (entry date, symbol) because `position_id` is
   assigned per run and does not match across arms:
   - the shared trades' `pnl_percent` deltas;
   - the unshared trades' counts and P&L;

   so a win can be attributed to shared-trade behaviour or to path (`lane-m-result.md` shape).
6. **This is a preset comparison, not a promotion.** No default flips. A promotion would need a
   ledger ACCEPT and the confirmation grid (`promotion-confirmation.md`).
