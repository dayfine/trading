## Why run 1's summary was still open

`merge_pr_when_clean()` (`orchestrator.yml:448`) polls **120 × 5s = 10 minutes**
for `mergeable_state == clean`. When the budget expires it does not fail — it
**falls through and attempts the merge anyway**, against a PR whose required
checks are still pending. The merge is refused, `jq -r '.merged // false'`
yields `false`, and the PR is left open. Nothing retries.

Measured exactly on #2426:

| event | time |
|---|---|
| PR opened | 09:14:16Z |
| poll budget expires | 09:24:16Z |
| `perf-tier1-smoke` completed | 09:21:21Z (in time) |
| **`build-and-test` completed** | **09:27:27Z — 191 s LATE** |

The long pole finished **more than three minutes after the automation stopped
waiting**. Run 1's own summary independently recorded `build-and-test` at "~15
minutes". The budget is set **below the routine duration of the check it exists
to wait for** — not an edge case, the normal path.

Created-to-merged lag across the last ten `ops/daily-*` PRs: 201, 25, 9, 64,
221, 23, 21, **1149**, 69, 11 minutes. **One** of ten plausibly merged inside
the window. *Stated as a proxy rather than proof* — the poll starts when the
bundle step runs, somewhat after PR creation, so the borderline rows are not
individually conclusive. #2426 is conclusive because the check-run completion
was measured directly against the deadline.

The failure is invisible **because** something eventually merges the PR, so in
retrospect every summary is on `main` and the automation looks fine. Filed as
**#2429**. Needs `workflow` scope.
