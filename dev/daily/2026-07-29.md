## The #2163 arc — a fix that was worse than the bug

`H-CHECK-SETE-DIAGNOSTICS` is a *diagnostics* defect, not a correctness one.
Under `set -e`, `VAR=$(cmd); CODE=$?` aborts before `CODE=$?` is reached, so a
genuine failure emits **no** output — non-zero exit, empty stdout, no
source-level error. That signature is precisely what `pr-merge-gates.md` lists as
an admissible *infra-flake exception*, so the hazard is a real regression being
waved through during triage as a sandbox race.

The audit itself was good: 22 candidates classified (3 defects, 19 safe), with
per-script reasons, and a negative-control self-test in the style that earned
#2155 its q5.

**Then the fix introduced a false green.** Two of the three defects were guarded
with `|| continue` on the file read. qc-behavioral built the case that
discriminates — a 350-line **violating** `lib/*.ml` made unreadable — and
measured:

- pre-fix: **exit 2**, a loud crash
- post-fix: `OK: all lib/*.ml files within limits`, **exit 0**

`|| continue` cannot tell *vanished* from *unreadable*, so in a merge-gating
linter it silently drops a file that actually violates the limit. It also
falsified the PR's own claim that no existing file's verdict changed. The
asymmetry is what made it a blocker rather than a FLAG: **the original bug
produced a correct failure with a bad shape; the regression produced a silent
wrong pass.** And the guard added to prevent regressions pinned only 1 of the 3
fixes — reverting both linter fixes left it green 2/2.

The rework fixed both, and was verified under **the same mutations that found
them**, by the same reviewer (which is why I resumed the original agents rather
than dispatching fresh ones):

- Unreadable-but-present → both linters exit 1 with a diagnostic naming the file.
  The decision is a *second* `[ -e ]` evaluated **after** the read fails, not the
  racy bare pre-check I warned about.
- **Vanished files are still tolerated** — a ghost file skips quietly, and a
  ghost followed by a real violation still reports the violation. This second
  direction is what separates a fix from an over-correction: hard-failing on a
  vanished file would have traded a false green for a flaky gate.
- Reverting each of the three fixes *alone* now turns the guard red every time.

**One detail worth keeping.** The author's fixture is a **directory masquerading
as a `.ml` file**, not the reviewer's `chmod 000`. The reviewer flagged this
upward against its own work: `chmod 000` only reproduces under an unprivileged
user and **would have silently passed under a root-running CI job** — which is
exactly how this container runs. The fixture that shipped is better than the one
that found the bug, and the rationale is recorded in-tree citing `access(2)`.
