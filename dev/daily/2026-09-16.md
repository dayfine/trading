### #2853 — the fix for #2850, built so it cannot ship inert

This is the direct answer to the run's central finding: make
`orchestrator_fastexit_gate.sh verify` **refuse a summary that is not from the
current run's date**, so a run that writes nothing fails with *that* as the
diagnostic instead of silently validating a two-day-old file.

The brief's hard constraint was self-activation. The workflow calls
`verify "$SUMMARY"` with **one** argument and cannot be edited from this runtime
(`workflow` scope unavailable), so a fix gated behind a new flag would ship
**inert** — exactly the trap #2836's disk guard fell into yesterday
("shipped callable but nothing calls it"). The agent:

- **Reproduced first.** Sourced the unpatched script as a lib, built a
  real-shaped NO-OP fixture dated `2026-09-14`, called `verify` as of
  `2026-09-16` → **`rc=0`, "NO-OP run OK"**. The defect confirmed by
  construction before any fix.
- Resolves the expected date as *optional 2nd positional → `$ORCHESTRATOR_EXPECTED_DATE`
  (`any` disables) → **real system UTC date***. The last fallback is what makes it
  fire on the existing one-argument call. It **verified that env var is set
  nowhere in the workflow**, and proved activation with two scenarios that
  compute "today"/"2 days ago" from the real clock and invoke the gate with
  exactly one argument.
- Accepts today **or yesterday** (UTC), so a run straddling midnight is not
  falsely failed; it only fires at >= 2 days stale — the measured case.

Two judgement calls, both argued from the script's own precedent rather than
from the brief:

- **rc=1, never rc=2.** In this script rc=2 means *"a real answer exists but a
  network call failed"*. A basename-vs-date comparison is fully determined from
  local inputs, so there is no "couldn't determine" state to fail closed on.
- **Unparsable basename passes through** rather than failing, matching
  `_verify_full_mode_dispatch_artifacts`'s TABLE-SHAPE GATE — *"an input shape
  this check doesn't recognise is not evidence of anything"* — which also keeps
  the pre-existing `#2634` fixtures green.

Mutation table, every mutant restored afterward:

| mutation | scenarios killed |
|---|---|
| freshness check → unconditional `return 0` | 4 |
| exact-date comparison → `if true` | 4 |
| delete yesterday-tolerance | 1 (midnight straddle) |
| delete the `any` escape hatch | 24 |
| unparsable basename → `return 1` | 1 (pass-through only; #2634 fixtures unaffected) |
