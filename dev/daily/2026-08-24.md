## What the QC passes actually found

### #2504 — the disease inside the cure, fourth-family instance, caught at the gate

The PR adds `report_conjuncts()` so a failing multi-conjunct assertion can say
*which* conjunct broke. qc-behavioral asked the one question that matters about a
diagnostic: **is anything exercising it?**

It fires only in the `else` branch of scenarios 21/22 — which on a green tree
**never executes**. Three mutations of the helper (early `return 0`; inverted
`[[ "$2" == "0" ]]`; `shift 1` instead of `shift 2`) each left the suite at
**60 passed / 0 failed, exit 0**. *The diagnostic this PR exists to add was
pinned by nothing.*

It blocked **narrowly and reasoned it explicitly**: the blast radius is bounded
(a broken helper degrades diagnostics to today's baseline and **cannot make a
gate pass that should fail** — not the vacuous-pass family), but **the file
already sets its own precedent** — scenario 42 exists for exactly this hazard
class and `_glob_count`'s docstring names it by ID. Landing an unexercised
diagnostic would reproduce the argument the PR was written to defeat.

Rework added **scenario 43**; all three mutations now turn the suite red,
re-derived independently by both reviewers. The behavioral re-review then probed
one step further — whether the scenario rests on a *single* assertion, since
under `shift 1` the label text coincidentally still matches. It neutralized the
count check and re-ran: **M1 and M2 are still caught by the label checks alone;
only M3 depends on the count.** That is the difference between "it passes" and
"I know why it passes."

**It also found a latent bug in `write_audit.sh` and correctly refused to fix
it here.** The `consecutive_rework_count` scan uses
`for f in $(ls -1 "$AUDIT_DIR"/*-"$FEATURE".json)`. When the glob matches **only**
a directory-shaped record, `ls -1 <dir>` lists that directory's (empty)
*contents* → **zero words** → the record is invisible, **no WARNING fires**, and
the count is silently **under-counted**. That is the unsafe direction the
`H-PREV-VERDICT-PIPEFAIL` design note says must never happen silently, and it
corrupts the input to the `>= 3` rework escalation. Filed with a repro rather
than bundled into a test-diagnosability PR.

### #2507 — a published number that was an artefact, not a measurement

qc-behavioral re-derived the mutation battery and found the sensitivity table's
**"top-N off-by-one → 834 trace lines moved"** was **not a measurement**. Both
directions move **35** lines. **834 is exactly the trace's total line count** —
reproduced *by accident* when a mutation failed to compile and the dump wrote an
empty file, so `diff` reported the whole baseline removed.

**The generalisable lesson, now guarded in the harness:** a mutant that fails to
*compile* produces an empty dump that reads as a **maximal** diff. The mutation
harness now refuses to report a count unless the mutant **built and wrote
non-empty output** — and that guard fired on two non-compiling mutants during the
rework session. The other three figures cannot share the mode: an empty dump
yields a count *exactly equal* to the total, whereas 21/17/490 are strictly
between 0 and the total, which requires partially-agreeing output.

It also found the **sector gate was entirely invisible to the instrument** —
deleting the sector conjunct from both admission paths left the trace
byte-identical (**0 of 834 lines**) and the suite **green**, while the `.mli`
claimed "each arm … is exercised." A surviving mutant far larger than the one
disclosed. Root cause: `Weak` was carried only by Stage-4 symbols (never long
candidates) and `Strong` only by Stage-2 symbols (never shorts) — **neither arm
had anything to reject.**

The rework chose the harder fix over the honest-narrowing one: two new fixture
symbols shape-identical to already-admitted groups so the sector rating is the
*only* difference. **Before: `moved=0/834, GREEN-SURVIVED`. After:
`moved=94/893, RED-DETECTED`.** It then re-ran the three-commit differential
