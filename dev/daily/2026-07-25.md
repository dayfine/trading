- **[info] Root cause found for the recurring agent Finish-Protocol violation — it is a
  tooling default, not agent negligence, and this is the most reusable finding of the
  run.** Three of this run's build-agent sessions ended their turn "waiting for a
  background verification task," the exact pattern `worktree-isolation.md` §Finish
  Protocol prohibits and that killed an agent's work on 07-24. The cause: **the `Bash`
  tool's default timeout is 120s**, and a full `dune runtest` takes ~3-5 minutes. Told
  only "run it in the foreground," an agent hits the 120s wall, backgrounds the job, and
  then has nothing to do but end its turn. **Fix: the brief must state the mechanism —
  "the `Bash` tool accepts an explicit `timeout` parameter in ms (max 600000); use
  `timeout: 600000` and chain the three gate commands in one call, echoing each exit
  code."** I gave that instruction to the last agent and it complied first try, in one
  call. Recommend folding this into `worktree-isolation.md` §Finish Protocol and every
  build-agent dispatch template.
