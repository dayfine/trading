## Root cause — truncated runs are indistinguishable from no-ops

`.github/workflows/orchestrator.yml`, step *Locate daily summary + detect no-op*:

```bash
SUMMARY="$(ls -t dev/daily/${DATE}.md dev/daily/${DATE}-run*.md 2>/dev/null | head -n 1 || true)"
if [ -z "$SUMMARY" ]; then
  SUMMARY="$(ls -t dev/daily/*.md 2>/dev/null | grep -v -- '-summary\.md$' | head -n 1 || true)"
fi
```

When a run writes no summary **for today**, the second branch silently substitutes
**the newest summary from any prior day**. Consequences, all three observed
yesterday:

1. The step reports success, so the run is green.
2. *Fail on escalations* reads `steps.publish-summary.outputs.summary_path` —
   i.e. **yesterday's** summary. A truncated run can therefore never fail the
   gate on its own escalations.
3. *Bundle budget … and auto-merge* is gated on `noop != 'true'`; yesterday's
   summary says `**Mode:** FULL PASS`, so it runs and targets an
   **already-merged** summary PR. The cost record goes nowhere.

Evidence — 2026-07-29 had **8** orchestrator runs; `dev/budget/` on `main` has
**5** records. Missing: `30472186063`, `30485938238`, `30496638558`. All
`ops/*` branches have since been swept, so those three records are
**unrecoverable**, not merely orphaned.
