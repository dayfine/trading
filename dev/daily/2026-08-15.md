## The `ops(budget)` review bypass: root cause found, and it is one line

This has been filed as an escalation for eight consecutive runs and is the
maintainer's stated #1 question. Prior runs described the *symptom* correctly
and proposed guards against it (a path check that `ops(budget)` PRs touch no
`*.ml`/`dune` file; an empty-diff-vs-base check). **Both are the wrong fix,
because the cause is not a policy gap — it is a branch-base bug.**

Measured this run. All three cited PRs, merged with **0 reviews**:

| PR | title | non-doc code it actually carried |
|---|---|---|
| #2224 | `ops(budget): record 2026-08-06-…` | `segmentation_test.ml` +31, `trend/test/dune` +1 |
| #2235 | `ops(budget): record 2026-08-07-…` | `trade_audit_report.ml` +62, `.mli` +28, its test +204 |
| #2309 | `ops(budget): record 2026-08-13-…` | `linter_file_length.sh` +183, its test +255, `dune` +23 |

**~787 lines of production and test code merged with zero review**, under titles
announcing a JSON cost record.

Now the commit lists, which is the part that identifies the cause:

```
#2309:  93f97e7e  harness: close the .mli blind spot in linter_file_length.sh (P0.1)
        a7de3723  fix(gate): exclude *.pp.mli from the .mli file-length scan
        6726895a  ops(budget): record 2026-08-13-31700595897 ($32.1972)

#2235:  cde30208  feat(backtest): render the split-safe basis tally + inert fraction …
        7f0dadd0  ops(budget): record 2026-08-07-31178553959 ($21.3693)
```

The budget commit is the **last** commit on each branch, not the only one. The
branch carries whatever was already sitting on the runner's HEAD.

**`orchestrator.yml:482`:**

```sh
git checkout -b "ops/budget-${BUDGET_BASENAME}"
```

No base ref. The fallback branch is cut from **the runner's current HEAD**, which
by that point in the job holds commits left behind by the run's own agents. The
subsequent `git add "$OUT_FILE"` correctly stages only the JSON — but the *PR
diff* is branch-vs-`main`, so every pre-existing commit rides along. The PR body
then asserts, in good faith and wrongly, *"Additive observational data only."*
`merge_pr_when_clean` auto-merges it with no review gate.

**The fix is one line:**

```sh
git fetch origin main && git checkout -B "ops/budget-${BUDGET_BASENAME}" origin/main
```

That makes the diff exactly one JSON file, makes the PR body's claim true, and
makes review-free auto-merge of that PR *safe* rather than merely *tolerated* —
which is the property the proposed path-check guards were trying to approximate
from the outside. Blocked on `.github/workflows/**` (needs a `workflow`-scoped
PAT — the same blocker as #1636 and H-BLAS).

If you want defence in depth as well, the empty-diff-vs-base check is still
worth having. But it should be the backstop, not the fix.
