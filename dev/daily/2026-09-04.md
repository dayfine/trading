## New harness gaps this run surfaced (both filed, neither fixed)

- **`H-QC-VERDICT-NEWLINE-COLLAPSE`** — a QC review can post with every newline
  stripped. It renders acceptably for a human but is **invisible to
  `pr_gate_status.sh`**, which anchors on `^## Verdict`. Happened once this run
  (#2663's re-structural), failed safe (read as *stale*, not *approved*), and was
  fixed by re-posting. Nothing detects it: the reviewer's `POST` returned success
  both times. A one-line check after posting — *count the newlines, assert
  `## Verdict` is at a line start* — closes it. The severity is that the merge
  gate's input channel has an undetected corruption mode.
- **`H-GATE-TWO-VERDICTS-ONE-SHA`** — a body-only fix (the correct, cheap response
  to a PR-body finding, since it changes no SHA and re-runs no CI) necessarily
  produces two verdicts at one SHA, which the SHA-keyed gate reader cannot rank.
  Two legitimate mechanisms interacting badly, not a bug in either. Options: rank
  by `submitted_at` within a SHA, or have the superseded review be dismissed. The
  first is a two-line change to the reader; both need a decision, not a patch.

Both are exactly the kind of merge-gate defect **#2664's own harness exists to
catch mechanically** — and both were found by hand, in the run that built it.
