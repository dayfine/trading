### Why two agents, and why QC waited rather than running beside them

Two hardware ceilings bind before dollars do, and they interact: the runner
allows **1 concurrent `dune`** (15 GB, memory-bound) and each agent worktree
costs **~16 GB** once it builds. A third agent buys no parallelism — the mutex
serializes the expensive part — while costing 16 GB linearly.

That also decided the QC timing. `qc-structural` runs `dune build @fmt` / `dune
build` / `dune runtest`, so dispatching it while a harness agent held the mutex
risks the failure mode measured in run `34757914354`: an **OOM-killed QC agent
returns `NEEDS_REWORK`, and the finding reads like a code defect when it is
purely a scheduling artifact.** That is worse than waiting — it is a wrong
verdict on a clean PR. QC was sequenced behind the second agent deliberately;
this is the capacity rule, not caution about queue depth.

I reclaimed agent A's worktree **the moment its PR was pushed** rather than
batching to end-of-run (`sweep-hygiene.md`; batching is what took run
`33962894987` from a survivable 69% to 100% and an ENOSPC). Disk held at 59-60%
throughout.

### #2834 — the survivor argument proved too much

arbitrary commit read as current-at-tip**, re-opening the false-MERGE class this

## The pattern worth keeping from this run

Three separate times, the most valuable output was **a correction to something
that was asserted rather than measured** — and in two of them the corrector was
correcting *its own side*:

| who corrected | what |
|---|---|
| me → the record | `git merge-base --is-ancestor` reported NOT-MERGED for two branches; both were squash-merged PRs. My "stale branch" escalation was wrong. |
| the reworker → its reviewer | B2 claimed "M4, M6 and M7 scatter onto pre-existing cases"; M6 does not. Measured each row instead of copying the claim. |
| the reviewer → itself | Re-review: *"My B2 generalised from two measured rows to a third I never measured. That is precisely the defect B2 itself was about."* |
| the agent → my brief | I asserted `.claude/rules/**` was writable, reasoning from a PR that had landed through a human merge. It is not. |
| me → the carried record | Three capability claims repeated across many summaries measured **false** this run. |

The common shape is an **inference standing in for a measurement**, surviving
because nothing re-checks it. That is the same shape as the defect class the two
merged PRs close (a green run indistinguishable from a productive one) and as
#2835 (a condition that cannot fail) and #2837 (a verdict nothing can read).

The operational lesson is narrow and actionable: **carried claims — capability
notes, mutation tables, "stale branch" heuristics, review findings — are
measurements with a date, not standing facts.** Every one that rotted this run had
been repeated verbatim for days.
