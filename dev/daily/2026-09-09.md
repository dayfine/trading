## Headline — the diagnosis behind five lost summaries is wrong, and the fix it implies would not have fixed them

`dev/status/harness.md` explains five consecutive lost daily summaries (09-06 →
09-08) this way: *"Step 8 publishes via `jj bookmark set` + `jj git push`, and `jj`
is exactly the tool `H-JJ-JST-BROKEN-GHA` already records as non-functional in this
image."*

I tested it instead of inheriting it. **`jj git push` is not broken in this image.**
I pushed a probe branch with it, successfully, on this exact container:

| op | exit | result |
|---|---|---|
| `jj status` / `jj log` | 0 | works |
| `jj bookmark set` | 0 | works |
| `jj git fetch` | **1** | `Git does not recognize required option: porcelain (note: supported version is 2.41.0)` |
| `jj git push` — **Step 8 exactly as written** | **1** | `Won't push commit … since it has no description and it has no author and/or committer set` |
| `jj git push` — after `jj config set --user` + `jj describe` | **0** | **pushed** (`probe/jj-git-push-test` → `87df5ec5`, since deleted) |

### The real root cause (D2)

Step 8 runs `git config user.email/user.name` — **git's** identity. **jj does not
read git's user config.** jj needs `jj config set --user user.name/user.email`. So
jj sees author `" <>"` and refuses. Step 8 also never runs `jj describe`, so `@`
is descriptionless, and jj refuses that too.

**Both are independently fatal**, isolated by measurement rather than assumed:
with identity set but the description empty, the push *still* fails
(`Won't push commit 5eba7631 since it has no description`); with a description but
no identity it fails on the author. **Step 8 supplies neither.**

### Why the correction matters more than the bug

`H-JJ-JST-BROKEN-GHA` proposes three fixes — install `gh`, pin an interoperating
jj/git pair, or delete the `jst` instructions. **None of them would have fixed the
lost summaries.** Upgrading git repairs `jj git fetch` and therefore `jst submit`
(the agent-PR-creation half) — and Step 8 would still have pushed nothing, because
its failure has nothing to do with the git version.

One harness item is conflating **two independent defects with different fixes**:

- **D1 — `jst` / agent PR creation.** A real version incompatibility: the image
  ships **git 2.34.1**; jj 0.39.0 requires **≥ 2.41.0** for `--porcelain`.
  `jst submit` runs `jj git fetch` and dies there. This half of the record is
  correct. Fix: upgrade git in the image.
- **D2 — Step 8 / lost summaries.** Unrelated to the git version. Fix: two lines,
  or repoint Step 8 at `dev/scripts/publish_daily_summary.sh`.

Filed as **issue #2741** with the full measurement table, because a summary is a
record and this needs to be a queue item — the 09-07 run learned that the
expensive way.

The general shape, which is the transferable part: **an outcome-correct diagnosis
can still be mechanism-wrong, and mechanism is what the fix is derived from.** The
record said "jj is broken" and was right that the jj path failed; it was wrong
about *why*, and every remedy it proposed followed from the wrong why.
