### Correction to a carried-forward suggestion

08-27's `[low]` proposed guarding the review-SHA sentinel by "validating it is
40 hex chars". **That remedy would reintroduce the bug it is next to.**
`pr_gate_status.sh` captures `[0-9a-f]{7,40}` *deliberately*: an earlier `{8,40}`
bound made PR #2397's two 7-character `Reviewed SHA: 9346b3b` reviews parse as
sha-**less**, which under aggregation means current-at-every-tip-forever — the
#2423 shape. Requiring exactly 40 re-breaks that.

Measured what the garbled sentinel actually does: `e29e4c71…6f7g` captures the
first **39** hex chars, which matches no tip, so the review reads **stale** —
the *conservative* direction. It can block a merge; it can never wave one
through. Correct fix shape: reject a hex run followed by another word character
as a **malformed sentinel that warns loudly**, rather than silently truncating
it (current) or letting it fall through to sha-less (dangerous).
