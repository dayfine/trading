## A verdict the gate could not read

#2456's structural review posted **successfully** — HTTP 200, correct `commit_id`,
verified by id. And it was **unparseable**:

```
len(body)        = 4570
real newlines    = 0
literal "\n"     = 43
anchored ^#+ Verdict match → NO MATCH
```

The agent hand-escaped the JSON instead of letting the serializer do it. The body
rendered as one wall of text, and the regex `pr_gate_status.sh` uses to find a
verdict returns nothing — so the gate reads **no verdict at all** from a review
whose author reported APPROVED.

I repaired it via `PUT /pulls/{n}/reviews/{id}` — **encoding only, not one word of
content** (43 literal escapes → 43 real newlines; the word-count delta of 632 → 661
is purely `\n\n`-glued tokens separating). Verdict now reads `APPROVED` to an
anchored parser.

**Three distinct QC delivery failures are now on record**, and they degrade in
detectability: a **stall** announces itself and leaves work on disk; a **phantom
review** announces success and leaves nothing; a **malformed body** announces
success, leaves a real artifact, and is invisible to both the human (who sees text)
and the machine (which sees no verdict). Only the third can pass a by-id check.

The control is now in the behavioral brief: build the payload with `json.dump`, then
GET it back and assert `body.count("\n") > 0`, `body.count("\\n") == 0`, and an
anchored `^#+ Verdict` match.

## What the next run should know

1. **Check `state`/`merged` immediately before merging, not just CI and verdicts.**
   A `PUT /merge` returns `"merged": true` for an already-merged PR, so the response
   is not evidence you did it.
2. **Verify a review is *parseable*, not merely present.** By-id existence was last
   run's control and it passed a review with zero real newlines. Assert real
   newlines, no literal `\n`, and an anchored `^#+ Verdict` match.
3. **Poll `state` in any watch loop.** Mine printed tip, mergeable_state and review
   count, and so missed the PR closing under it for nine minutes. `mergeable_state`
   flipping to `unknown` is the tell.
4. **Look for a concurrent pipeline before dispatching QC.** Recent reviews or
   `fix(review):` commits within the last ~30 minutes mean another actor owns the
   PR. Dispatching anyway costs a full pipeline and changes nothing.
5. **A verdict pinned to the tip may have read a different commit.** GitHub pins a
   review to the tip at post time, not the SHA the reviewer read. Always compare the
   `Reviewed SHA:` line in the **body** against `commit_id`.
6. **The book is not available in GHA** (#2457). Do not brief a behavioral agent to
   primary-verify from source here; ask it to flag what it could not resolve.
7. **You can file an issue but not comment on one.** Plan corrections onto a PR.
8. **Give reviewers a live counter-example, not just the issue.** The #2452 shape is
   what stopped #2456 from shipping a rule that would have false-blocked approved
   PRs.
9. **#2456 is held by a `do-not-merge` label I applied — do not remove it to merge.**
   It is waiting on a human answer to Question 1, not on a gate. Label writes work
   from this token (200) even though issue comments do not (403), so **the label is
   the orchestrator's one reliable way to stop a concurrent actor.** Use it.
10. **Ask the reviewer to judge your scope decisions, not just the code.** I
    restricted #2456's rework to docs-and-tests, which caused a real bug to be
    *pinned* rather than fixed. Handing that call back to the reviewer explicitly —
    "this was mine to answer for, not the author's" — is how it gets caught.
11. **Replaying both readers over the live review corpus is the standing test for
    any `_gate` change.** The ~14% base rate was invisible in the diff and only
    appeared by replaying 166 real reviews across 35 PRs.
