## #2588 root cause — found, reproduced, filed as #2598

08-28 measured that `dune build @fmt` exits 1 while `fmt_check.sh` exits 0 on the
same tree, **could not pin the mechanism**, and filed #2588 with the cause
recorded as unresolved. It is now pinned:

> `.ocamlformat` lives at `trading/.ocamlformat`. The nearest `dune-project` sits
> one level **deeper**, at `trading/trading/dune-project`. ocamlformat's ancestor
> search stops at the nearest detected project root — **below** its own config —
> so it finds no config, **disables itself, and passes every file through
> unchanged**. `ocamlformat --check <realpath>` on a deliberately over-margin line
> printed `Warning: Ocamlformat disabled ... (root: trading)` and exited **0**.
> `dune build @fmt` is unaffected: `_build/default/` contains `.ocamlformat` but
> **no** `dune-project`, so the search resolves cleanly there.

`fmt_check.sh` is therefore a **permanent silent no-op**, not a flake — and it is
wired into `dune runtest`, so a green `runtest` says nothing about formatting.
Reproduced live on #2597: `dune build @fmt` red on 10 files while `fmt_check.sh`,
running inline in the same `dune runtest`, said OK.

This compounds #2588's ordering problem: `ci.yml:104` is `dune runtest` and line
109 is `dune build @fmt` as a *separate* step, so a PR whose tests fail never
reaches the only working formatting gate — and the one that does run inline always
passes.
