### Correction to my own filed issue #2632

**#2632's body says "five consecutive weeks (08-03 → 08-31)". That is a
substantial undercount and should be read as ≥16 consecutive failures back to
2026-05-18 — every run GitHub still retains.**

The 5 came from the cross-workflow list
(`/actions/runs?event=schedule&status=failure&per_page=20`), whose 20-item page
only reaches back to 08-03; I read a pagination boundary as the start of the
streak. Querying the workflow directly
(`/actions/workflows/weekly-start-sweep.yml/runs?per_page=100`) returns 16 runs
and **all 16 are failures**, so the true streak is at least 16 and the workflow
may never have been green in retained history.

The issue could not be corrected in place: `PATCH /issues/<n>` and
`POST /issues/<n>/comments` both return **403** for this token (see §Capabilities
in the daily summary). The correction lives here and in the daily summary.

The direction of the error matters — it makes the defect **older and worse**,
not milder, so the filed remediation still stands. But a wrong denominator in a
filed issue is exactly the class of defect this pipeline keeps catching in its
own work, and it was mine.
