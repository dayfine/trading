## New findings this run

1. **`write_audit.sh` writes audit records mode `0600` instead of `0644`** — a silent
   regression introduced by #2169 (H-AUDIT-ATOMIC-WRITE). `mktemp` creates `0600` by design
   (ignores umask) and `mv -f` preserves the temp file's mode; there is no `chmod` after the
   rename. Verified empirically this run: every record committed before #2169 is `0644`; the
   record this run wrote (`2026-08-03-harness-prev-verdict-pipefail-harness.json`) is `0600`,
   under `umask 0022`. Functionally inert today (both consumers run as the same user), but it
   is undocumented drift — and note the interaction: a record another user cannot read is
   exactly the grep-exit-2 "unreadable prior record" case #2184 just hardened against. One-line
   fix: `chmod 644 "$OUTPUT_FILE"` after the `mv`.
