## Why the local `dune` build gate was not run

Same reasoning as 2026-09-14 run 2, and it held again today. This runner is
**memory-bound at 15 GB with a cap of one `dune` in flight**
(`.claude/rules/container-capacity-scheduling.md` §"GHA runner"); two concurrent
OCaml links OOM-killed an agent on 2026-09-13 (run 34757914354, exit 137, which
produced a false `NEEDS_REWORK` that was entirely about scheduling).

Two agents were dispatched **before** this report was written and were holding the
dune mutex. An orchestrator-held `dune runtest` would have serialized both of them
behind a ~25-minute build — which is precisely what 2026-09-14 run 1 did, and it
is why that run lost all three of its agents (#2810).

CI publishes the same measurement for the same commit across a **wider** surface
(five workflows vs one local `dune runtest`), already completed, at zero cost to
the mutex. That is a strictly better instrument here, not a concession.
