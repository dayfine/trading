## Step 6.2's documented invocation is still wrong -- 5th consecutive run

```
$ dev/lib/run-in-env.sh sh trading/devtools/checks/status_file_integrity.sh
sh: 0: cannot open trading/devtools/checks/status_file_integrity.sh: No such file
exit=2
```

`run-in-env.sh` resolves `PROJECT_ROOT` to `<repo>/trading`, so the path passed to
it must already be relative to that. The correct form is:

```
$ dev/lib/run-in-env.sh sh devtools/checks/status_file_integrity.sh
OK: all dev/status/*.md files have required fields.
exit=0
```

An orchestrator trusting the documented form would escalate a phantom failure.
The fix lives in `.claude/agents/lead-orchestrator.md` Step 6.2, which is not
writable from this runtime (Claude Code's self-modification guard). Reported
every run since 2026-08-05.

## New this run: a `git`-shelling check passes locally for the wrong reason

`trading/devtools/checks/tracked_artifact_linter.sh` (PR #2252) shells out to
`git ls-files`. It passed for its author and for both QC agents in this
container, and failed in CI with:

```
fatal: detected dubious ownership in repository at '/__w/trading/trading'
```

Cause: `actions/checkout` adds the repo to `safe.directory` inside a **temporary
`HOME`** which the dune sandbox subprocess does not inherit. The local passes
were an artifact of the orchestrator having run
`git config --global --add safe.directory ...` during Step 1 -- that write lands
in the real `~/.gitconfig`, which every agent in the shared container inherits.

Reproduction (independent of any agent):

```
$ env HOME=/tmp/nohome git -C /__w/trading/trading ls-files -i -c --exclude-standard
fatal: detected dubious ownership in repository at '/__w/trading/trading'
EXIT=128

$ env HOME=/tmp/nohome git -c safe.directory=/__w/trading/trading -C /__w/trading/trading \
    ls-files -i -c --exclude-standard
EXIT=0   (1334 paths)
```

**Standing hazard for any future check that shells out to `git`**: local
verification in this container cannot detect it. Fixed in #2252 via
`git -c safe.directory="$REPO_ROOT" -c core.excludesFile=/dev/null`, plus an
explicit git-error-vs-violation branch so a git failure now emits a `FAIL:` line
naming the cause instead of dying silently under `set -e`.
