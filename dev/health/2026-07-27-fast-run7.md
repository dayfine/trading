## How the gate was established this run

The usual Step 6.1 procedure (a local `dune build && dune runtest --force`) was
attempted twice and **neither attempt produced a usable result**. Both are
recorded here because each failure mode is a trap that can be misread as a
verdict:

1. **Attempt 1 — `dune: command not found`, exit 127.** Invoked `dune` directly
   without the opam environment. Exit 127 is *not* a red build; it is "the
   command never ran". Had this been pattern-matched as a failure it would have
   produced a false `[critical]` "main baseline RED".
2. **Attempt 2 — SIGKILL, exit 137 (OOM).** Run from a clean isolated worktree
   with the correct incantation, but concurrently with three dispatched agents
   each running their own full `dune build`. The container is **4 CPU / 16 GB**;
   dune defaults to `-j 4` per tree, so four concurrent full builds request ~16
   parallel OCaml compiler processes. The build was OOM-killed. Exit 137 is
   likewise *not* a red build — it is the kernel reclaiming memory. See the
   capacity escalation in the daily summary.
