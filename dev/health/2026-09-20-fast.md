that moment contained this run's in-progress Step 5.5 index reconcile. Result:

```

had just written came to 281 chars against a 250-char cap. Not a main-baseline
regression: the row did not exist on `main` until this run created it.

runner:

```

    (15657/20480 bytes, all table rows <= 250 chars).      exit 0
OK: all dev/status/*.md files have required fields.        exit 0

Two things worth recording:

1. **The gate caught the orchestrator's own edit before it reached a PR.** The
   `index_size_linter` exists because reconcile cells accrete run history; it
   fired on the first run that gave it something to fire on, at the cheapest
   possible moment.
2. **`RUNTEST_EXIT=1` here does NOT mean main is red**, and a future reader
   scanning for "was the baseline green" must not read it that way. Main's own
   evidence is independent: the last CI on `d59ad4be` passed `build-and-test`,
   `perf-tier1-smoke`, `golden-sp500-5y` and `golden-custom-universe`. Reporting
   a tree-state failure as a baseline failure is precisely the stale-`[critical]`
   cascade the orchestrator's Step 1c exists to prevent.
