Not a build-gate failure; recorded here because it is invisible to every gate.

```json

Stop         -> bash /Users/difan/Projects/trading-1/dev/scripts/cleanup_merged_worktrees.sh
```

Both are **macOS-local absolute paths** that cannot exist on a GHA runner, so
both hooks fail on every containerised run of every workflow that loads project
settings (`settingSources: ["user","project","local"]` -- confirmed in the SDK
options block of all three container workflows' logs).

Same defect class as the book-authority path in
`.claude/rules/book-as-authority.md`, which at least *documents* that it is
local-only and gives a detection snippet. These do not. The repo-relative form
(`bash dev/scripts/sweep_stale_worktrees.sh ...`) would work in both
environments. Filed to `dev/status/harness.md` as
`H-SETTINGS-HOOKS-ABSOLUTE-LOCAL-PATH`.

It is **not** the cause of the `track-pacer-weekly` failure (#2662) -- the two
workflows that succeed load the identical settings file and fail the identical
hooks. See the daily summary for that investigation.
