### What this establishes, and what it does not

- **Establishes:** the failure is **not** a regression on main and **not**
  deterministic across runners. Run 3's own "likeliest reading" —
  host/BLAS-kernel dependence — is now the surviving hypothesis, and run 3's
  proposed action (retract "#2009 closed the flake") should **not** be taken on
  the strength of a red gate, because the gate is not red here.
- **Does not establish:** that the underlying flake is fixed. It is intermittent
  *across hosts*, apparently deterministic *within* a host. Runs 1, 2 and 4 saw
  exit 0; run 3 saw exit 1 with 3/3 reproduction. That is four datapoints
  consistent with host-dependence and inconsistent with a code regression.
- **Therefore:** downgraded from `[critical]` to `[medium]`. Per Step 1c, a
  verification that comes back clean must not be carried as `[critical]` — the
  tag fires the "Fail on escalations" GHA gate.

### Two root-cause hypotheses eliminated this run (by reading, not guessing)

1. **"A failed `potrf` leaves `k` partially overwritten, so the retry jitters a
   corrupted matrix and can never converge."** — **FALSE.**
   `Owl.Linalg.D.chol` at `owl_linalg_generic.ml:288` opens with
   `let x = M.copy x in` before calling `Owl_lapacke.potrf`. Each attempt sees a
   clean copy. This was the most attractive theory; it is dead.
2. **"`max_added_jitter = 1e-2 *. signal_variance` collapses to ~0, so the
   escalation adds nothing."** — **FALSE** for the BO path.
   `bayesian_opt.ml:219` fixes `_signal_variance = 1.0`, so the cap is `1e-2`
   absolute. With `noise_variance = 1e-6` growing x10 per retry, cumulative
   added jitter reaches ~1.1e-2 — about 1.1% of a ~1.0 diagonal, which is ample
   to restore positive-definiteness for merely duplicated observation points.

**Surviving suspects** (for whoever picks this up): non-finite entries
(`NaN`/`inf`) in the kernel matrix, against which no amount of jitter helps and
which would produce exactly the observed "exhausts all 6 attempts and re-raises";
or a genuine BLAS-kernel difference across runner CPU generations (run 3's host
was an AVX-512 `Xeon 6973P-C`; `ci.yml` already carries a dedicated CPU-flag
smoke step, which is itself evidence this class of problem has bitten before).
