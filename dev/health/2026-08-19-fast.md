Failure modes are four recurring shapes, all mechanical: `End of text is not
allowed in '[...]'`, `Blank line is not allowed in '[...]'`, `Unpaired ']'`
(suggestion: `\]`), and `{N ...}` misparsed as a section heading — the last is
what a literal set like `{13, 26, 52}` inside a docstring does.

**Still non-gating** (`@fmt` exits 0), so this is not an escalation. But the
recorded scope was wrong by an order of magnitude, and the `cleanup.md` entry
scoped to one file / one line would have sent a cleanup agent to fix 1 of 26.
The entry has been corrected rather than a second one filed.

This is the repo's signature defect class again — a correct observation
("there is a warning at 1458") restated as a complete enumeration ("one
warning"). It is worth noting that it appeared in a *health report*, i.e. the
artifact whose whole job is to enumerate.
