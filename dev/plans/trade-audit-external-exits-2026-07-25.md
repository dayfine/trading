# Plan: `trade_audit.sexp` visibility for externally-generated exits (#2076)

## Context

Issue #2076 is the remaining half of #2057. #2057's first half (PR #2074,
merged as `c9dfb9ba`) fixed the `trades.csv` / `Stop_log` sink: margin-driven
exits (`margin_call` / `buyin_stress` / `maintenance_reduce`, all
`Position.StrategySignal`) are generated by `Trading_simulation.Margin_runner.tick`
inside `Simulator._process_step_day`, *after* the strategy's own
`on_market_close` call returns — outside any observer that was wired only at
the strategy-call boundary. #2074 added `Simulator.dependencies.on_transitions`,
an optional per-step observer invoked with the FINAL post-dedup transition list
(strategy's surviving transitions + margin's), and wired it in
`Backtest.Panel_runner` to `Stop_log.record_transitions`.

The richer `trade_audit.sexp` sink (`Backtest.Trade_audit`, with per-exit
macro/stage/RS context) is populated by
`Weinstein_trading.Exit_audit_capture.emit_for_list`, called only from
`weinstein_strategy.ml`'s stops pass (`_run_stops_pass`), which only sees the
exit transitions coming out of `Stops_runner.update`. This is a **strictly
narrower** slice than `on_transitions` sees:

- margin exits (`margin_call`, `buyin_stress`, `maintenance_reduce`) — never
  reach `Exit_audit_capture` at all (generated below the Weinstein layer,
  after the strategy call returns).
- `stage3_force_exit`, `laggard_rotation`, `extension_stop`,
  `macro_bearish_trim` — strategy-emitted `TriggerExit`s from OTHER runners
  than `Stops_runner`, never routed through `Exit_audit_capture` either
  (pre-existing gap per #2074's investigation note, not margin-specific).
- `harvest_rotate` — emits `TriggerPartialExit`, not `TriggerExit`. It trims
  part of a position rather than closing it, so it does not represent a
  round-trip close in the first place; out of scope for `exit_decision`
  (which models a full position close) regardless of this fix.

For all of the above, `Trade_audit`'s bucket for that position has an `entry`
(recorded via the strategy's own `Audit_recorder` path at entry time) but
`exit_` stays `None` forever — the audit shows the position as "still open"
even though `trades.csv` correctly shows it closed with a real
`exit_trigger` label.

## Approach

**Chosen: a parallel, lighter-weight "reason-only" exit record on
`Trade_audit`, populated via the same `on_transitions` hook, mirroring
`Stop_log.record_transitions`'s wiring exactly.**

1. Add a new type `Trade_audit.external_exit_decision` — `symbol`,
   `exit_date`, `position_id`, `exit_trigger : Stop_log.exit_trigger`. No
   macro/stage/RS fields: the `on_transitions` observer sits in
   `trading/trading/backtest/`, below the Weinstein analysis layer, and
   architecturally cannot fabricate that context (same reasoning #2074's
   investigation note already established for why this isn't fixed by
   fabricating values).

2. Add an **additive, optional** field to `audit_record`:
   `external_exit : external_exit_decision option [@sexp.option]`. `[@sexp.option]`
   means the field is entirely omitted from the sexp when `None`, so old
   `trade_audit.sexp` files (written before this change, which have no such
   key at all) still parse via `[%of_sexp: audit_record]` — this is the
   "readers of existing files must still parse" requirement. `exit_` (the
   fully-enriched `exit_decision option`) is untouched — its shape, meaning,
   and every existing consumer keep working unchanged.

3. Add `Trade_audit.record_transitions : t -> Position.transition list -> unit`,
   directly modeled on `Stop_log.record_transitions`: for every
   `TriggerExit { exit_reason; _ }` transition, look up the bucket by
   `trans.position_id`. If the bucket exists (i.e. an `entry` was previously
   recorded — mirrors `record_exit`'s existing "no entry → drop" contract)
   **and** its `bucket_exit` (enriched) is still `None`, set
   `bucket_external_exit` from the transition (`symbol` from
   `bucket_entry.symbol`, `exit_trigger` via the existing public
   `Stop_log.exit_trigger_of_reason`). If `bucket_exit` is already `Some _`
   (the strategy's own enriched path already recorded a full `exit_decision`
   for this position — the `Stops_runner`-triggered case), this is a
   deliberate no-op: **enriched always wins over reason-only**, so a fully
   context-rich record is never downgraded or duplicated.

   This is safe by construction because of call ordering within one
   simulator step (`Simulator._process_step_day`): the strategy's own
   `on_market_close` call (which runs `_run_stops_pass` →
   `Exit_audit_capture.emit_for_list` → `Audit_recorder.record_exit` →
   `Trade_audit.record_exit`, i.e. the enriched path) always completes
   *before* `on_transitions` fires for that step's final transition list. So
   by the time `record_transitions` runs, any enriched exit for that step is
   already in place.

   Only `TriggerExit` is handled (not `TriggerPartialExit` — `harvest_rotate`
   is the only user of that kind and, per Context above, a partial trim isn't
   a round-trip close).

4. Wire it in `Backtest.Panel_runner._make_simulator`: compose the single
   `on_transitions` slot into both observers —
   `~on_transitions:(fun ts -> Stop_log.record_transitions stop_log ts;
   Trade_audit.record_transitions r.trade_audit ts)` — since
   `Simulator.dependencies.on_transitions` is a single optional slot, not a
   list.

This gives:
- Margin exits (#2076's stated scope) — fixed.
- `stage3_force_exit` / `laggard_rotation` / `extension_stop` /
  `macro_bearish_trim` — fixed for free (same generic `TriggerExit` +
  "no entry-side context available" path; no per-label special-casing
  needed). Pinned with one parametrized test.
- `harvest_rotate` — correctly NOT covered (see Context); noted as a
  deliberate non-fix, not a residual gap, in the status file.

### Rejected alternatives

- **Fabricate macro/stage/RS context for external exits** (reuse the last
  cascade snapshot, or default zeroed values). Rejected per the issue's own
  guidance: "a fabricated-context record is worse than an explicitly-partial
  one." Also `Margin_runner` lives in `trading/trading/simulation/`, strictly
  below the Weinstein-specific analysis layer (`analysis/weinstein` /
  `trading/trading/weinstein/`) — it has no access to a `Macro.result` /
  `Stage.result` to fabricate from even if we wanted to.
- **Turn `exit_` into a variant** (`No_exit | Enriched of exit_decision |
  External of external_exit_decision`) instead of adding a parallel optional
  field. Rejected: it renames/reshapes the existing `exit_` field, forcing
  edits to every consumer that pattern-matches `audit_record.exit_` as an
  `option` (`trade_audit_report.ml`, `trade_audit_ratings.ml`,
  `decision_grading_bin.ml`, 5 test files) purely to preserve exhaustiveness
  — much larger blast radius for the same outcome, and loses the "old files
  still parse" property for free (`[@sexp.option]` on an added field is a
  strictly additive, non-breaking sexp shape change; renaming a field is
  not).
- **Give `Margin_runner` a reference to `Audit_recorder`.** Explicitly
  disallowed by the issue and by `docs/design/eng-design-4-simulation-tuning.md`'s
  layering: `trading/trading/simulation/` must not depend on
  `trading/trading/weinstein/` — the whole point of #2074's `on_transitions`
  hook is to keep the observer strategy-agnostic and stay below that layer.

## Out of scope (explicitly not doing)

- **Not** surfacing `external_exit` in `trade_audit_report.ml`'s markdown /
  HTML rendering or in `trade_audit_ratings.ml`'s scoring. The issue's ask is
  the `trade_audit.sexp` **capture** gap; wiring it into the human-facing
  report is a separate, additive follow-up (noted in the status file) — it
  touches rendering code this PR doesn't otherwise need to touch, and risks
  scope creep into report-formatting decisions.
- **Not** touching `Margin_runner`, `Long_maintenance`, `Short_buyin`, or any
  margin mechanics — read-only consumer of the transitions they already
  produce.
- **Not** restructuring `Audit_recorder`'s public interface — `Weinstein_trading.Audit_recorder`
  and `Exit_audit_capture` are untouched; the new path is a second, parallel,
  backtest-layer-only route into `Trade_audit`, not a change to how the
  strategy's own enriched path works.
- **Not** fixing `harvest_rotate`'s absence from `trade_audit.sexp` — it's a
  partial trim, not a round-trip close; the round-trip `exit_decision` model
  doesn't apply.
- **Not** changing `weinstein_strategy.ml`'s stop state machine or any core
  strategy logic.

## Risks / unknowns

- **Ordering assumption** (strategy call always completes before
  `on_transitions` fires within one step) — already established as true by
  #2074 and its tests; this PR relies on the same invariant, doesn't
  introduce a new one. Verified by reading `Simulator._process_step_day`
  before implementing.
- **`[@sexp.option]` interaction with the existing hand-rolled
  `sexp_of_audit_records` / `audit_records_of_sexp` top-level codec** — these
  delegate to `[%sexp_of: audit_record list]` / `[%of_sexp: audit_record
  list]`, so the ppx-derived per-field behavior applies automatically; no
  separate hand-written (de)serialization to keep in sync.

## Acceptance criteria

- `Trade_audit.record_transitions` exists, is exported with a doc comment,
  and is unit-tested for: margin-label capture, a second `StrategySignal`
  label (e.g. `stage3_force_exit`) captured via the same generic path,
  enriched-exit-wins (no overwrite), and the no-entry-recorded → drop case.
- `Panel_runner` wires the composed `on_transitions` and still builds.
- An end-to-end test drives a real `Simulator.run` with margin enabled and
  observes `external_exit` populated on the resulting `Trade_audit` record.
- `dune build @fmt`, `dune build`, `dune runtest` all exit 0.
- Old-shape `trade_audit.sexp` (no `external_exit` key) still parses —
  covered implicitly by `[@sexp.option]`'s documented semantics; call out in
  PR body rather than hand-writing a fixture parse test (no old fixture file
  is read back by any current code path — `trade_audit_report.ml` reads
  fresh per-run output only).
